# 排错

按出现阶段找，每条给「看到什么 → 为什么 → 改哪里」。平台日志在 `backend/logs/app.log`（接口与分支）和 `backend/logs/dev-all.log`（重启原因）。

---

## A. 接口发现（探针）

**`ModuleNotFoundError: No module named 'xxx'`**

模块名或解释器不对。先确认三件事一致：登记目录是**包所在目录**（`records.py` 的父目录，不是它上一级），`module` 是可 import 的名字（有包就是 `pkg.mod`），解释器里装了这个工程的全部依赖。

```bash
# 用登记的那个解释器手工验一遍
"<解释器>" -c "import sys; sys.path.insert(0, r'<工程目录>'); import <模块>; print('ok')"
```

**探针超时 / 卡住**

模块 import 时做了重活：起服务、等 stdin、弹窗口、下载、连数据库。挪进函数或 `if __name__ == "__main__"`。GUI 工程只 import model 层。

**`ImportError: attempted relative import with no known parent package`**

模块用了相对导入但没有包结构。加 `__init__.py` 并按包名登记（`module` 写成 `pkg.sub`），或在适配层改绝对导入。

**中文报 `UnicodeDecodeError`**

业务代码 `open()` 没写 `encoding`。平台给子进程设了 `PYTHONIOENCODING=utf-8`，但**不会**设 `PYTHONUTF8`（避免打挂读 GBK 的老脚本），所以文件读写要显式编码。

**只能看到一部分函数**

模块定义了 `__all__` 就只认它；没有 `__all__` 时只收 `__module__` 等于本模块的公开函数。`from x import y` 进来的函数不算本模块的。要精确控制目录就写 `__all__`。

**类的方法看不到**

探针只列公开属性；`_` 开头的跳过。继承来的方法会列出来（`dir()` 的口径）。

**`factory 不是可调用对象`**

旧登记字段 `factory` 有值但指向的不是类/函数。构造改在流程的构造槽里做，`factory` 留空。

## B. 校验与发布

**`接口 X 尚未成功探测`**

探测结果里没有这个 key。九成是 `interface` 与目录里的名字不一致：实例方法要写 `类.方法`（`DataCenter.fetch`），构造器写类名（`DataCenter`），工厂写函数名。`function` 也要对：它是末级名（`fetch`）。

**`节点 n 的 fetch 槽缺少必填参数 points`**

方法有必填参数没给来源。加 `"points": {"lit": 24}` 或从启动输入/现场参数取。注意给了 `default` 的参数在探针里不算必填。

**`节点 n 的 fetch 槽包含接口未声明的参数`**

参数名拼错，或方法升级改了名。以探针输出为准，别照抄文档。

**`节点 n 的 fetch 槽引用了未在开始节点声明的启动输入 device`**

`{"source": "input", "name": "device"}` 要求开始节点 `inputs` 里有同名项。

**`节点 n 的 fetch 槽引用了未声明的现场参数 channel`**

节点要加 `runtimeInputs`：

```json
"runtimeInputs": [{"name": "channel", "type": "text", "required": true}]
```

**`节点 n 的 present 槽引用了上一槽结果，但本节点没有拉取或处理槽`**

`previous` 只指本节点内上一步。这个节点没有 fetch/process，就没有「上一步」。要么补 fetch，要么把参数改成 `lit`/`input`/`parameter`，要么直接调对象方法（参数从对象里取）。

**`节点 n 的处理槽引用了上一槽结果，但本节点没有拉取槽`**

同理：process 的上一步只能是 fetch。

**`实例方法 X 必须指定目标对象`**

`object` 留空了。构造槽里给对象起个名，这里填同一个名字。

**`构造槽的对象名重复` / `未声明的对象`**

对象名是全局键，一个名字只能构造一次；其余槽引用的名字必须在构造槽里出现过。

**`排查节点缺少展示槽 / 判定槽`**

v1.17 起排查节点必须四槽齐（展示 + 判定），只有完全没有任何槽位的旧文档才按人工节点跑。要么配齐，要么把节点改成「排查动作」。

**`分类节点至少需要两条出线` / `出线只能连到排查节点`**

分类是分流说明，至少两个选项、每个选项直接连一个排查节点；选项文案取目标排查节点的 title。

**`存在没有出口的环`**

回退链路可以成环，但环上必须有节点能走出去（连到环外）。跳转节点最容易犯：`jump` 指回自己。

**`这是旧格式流程` / `节点仍在使用已移除的旧接入字段`**

v1.16 的 `composition`、`binding`、`operation`、`pipeline` 等字段全部不再接受。按 `references/workflow-format.md` 重写槽位。

## C. 运行时

**「执行报错」待办，日志里是 `execution/exception`**

业务方法抛异常。平台**不会**把异常当「否」，会挂起这条分支等人决定回退或结束。看 traceback 最后一条业务栈帧；`smoke_run.py` 会把异常行和位置提炼出来。

**`ValueError: 展示槽 X 调用失败：'list' object is not a mapping`**

`view` 与返回形状不匹配。最常见：`line` 配了返回 dict 的方法，或 `table` 配了返回数组的方法。对照第 6 节的契约改 `view` 或改方法的返回。

```
line    → 非空数字数组
metrics → [{"label","value","unit"?}]
table   → {"columns": [...], "rows": [[...]]}
image   → 64 位十六进制摘要
text    → 字符串或可 JSON 化对象
```

**`image 展示块的 src 必须是附件摘要`**

业务返回了文件路径或 URL。图片必须先 `node_sdk.save_file(bytes)`；只收 png/jpg/webp/gif，单张 10 MB 以内。

**`TypeError: cannot pickle 'xxx' object`**

对象图里有不可序列化的成员：连接、锁、窗口、线程、生成器、lambda、文件句柄。用 `__getstate__` 排除，或改成调用时临时创建（`with connect(...)`）。不要用「静默丢字段」的方式绕过——恢复后行为会变。

**`函数内临时类、闭包` 构造后无法恢复**

类定义在函数里或闭包里，pickle 找不到它。把类挪到模块顶层。

**人工等待时进程被杀 / 重启后实例不动**

平台重启不自动续跑，这是当前明确不做的能力。重启后未完成实例需要人工处理。

**签名不一致 `signature/changed`**

发布后有人改了方法参数表。冻结的签名与当前代码不符时，**还没跑过任何节点**的实例会直接失败。重新发布即可；已经跑过的实例走人工恢复，不再拦。

## D. 结果不对（但没报错）

**下一个节点拿不到上一个节点的结果**

按设计如此：跨节点不传值。下一个节点自己 fetch（同参数命中缓存），或从上一步存进对象的属性里读。

**数据是旧的 / 改了源文件没生效**

三层原因，按顺序查：

1. 发布快照：实例用的是**发布版本**的源码副本，改原工程只影响新发布的版本
2. 取数缓存：同 `{工程, 模块, 接口, 对象, 参数}` 一次诊断只取一次
3. 底层数据源本身有缓存

要强制重取，给拉取槽加 `"useCache": false`（跳过读缓存，取完仍写回）。

**并行分支之间互相看不见对方的对象改动**

分叉时继承当时的对象与缓存，之后各分支独立进程、独立内存。要共享状态只能在分叉前算好，或让每个分支自己取。

**回退后没有重新取数**

符合预期：回退复用到访时已取得的上游值，拉取缓存继续保留。要新值就在目标节点用 `useCache: false`。

**判定结果和现场不一致**

先看执行轨迹里的 `reason`：自动判定必须把依据写进返回值，否则平台只能记「由判定方法给出结论」。再确认阈值来自哪里（启动输入、现场参数还是硬编码 `lit`）。

**串行跑到「问题解决」就停了**

串行模式下成功且还有待排查思路时会询问「结束 / 继续」，这不是暂停。并行模式则各分支独立跑完。

## E. 登记与导入

**工程名写错了**

登记后不可改：它出现在槽位、签名与已发布版本里。删掉重建会导致已有流程找不到实现，只能重建工程并按新名字重配槽位。

**删了工程，流程报错**

删除不检查引用。已引用它的流程不会立刻报错，但重新探测或发布会失败。

**导入返回 422**

按响应里的 `issues` 逐条改；离线先跑 `validate_workflow.py`，报错文案一致。旧格式（`format` 不是 1 的编辑投影、含已移除字段）会被拒。

**`format=2` 的文件导不进去**

那是存储格式，导入接口要 `format: 1`。把 `flow` 里的节点与 `bindings.nodes` 里的 `slots` 合并回单层再导入。

## 快速定位顺序

1. 先看脚本输出的「模式」：`独立预检` 说明本机没有可导入的 NewDiag 仓库，结论来自内置规则
2. `probe_project.py` 能列出接口吗 → 不能就是 A 类
3. `validate_workflow.py` 有没有 error → 有就是 B 类
4. `smoke_run.py` 能不能到终止 → 跳过说明不在平台模式；报错是 C 类，走错分支是 D 类
5. 都过了但平台里行为不同 → 看发布版本、实例模式（串/并/手动）、启动输入是否与冒烟一致
